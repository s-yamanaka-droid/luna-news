| 項目 | 確定内容 |

| **差別化の主戦場** | ① 記事の**独自分析・オピニオン** ② 明日から使える**実用性** ③ **速報性・網羅性**。※「画像の見栄え」は主軸に選ばれていない＝画像は"悪くなければ良い＋Threads映え"まで |

## 2. 100点の定義（測定可能な成功条件）

「動く」でなく、**次の条件を全て満たしたら100点**とする。Sonnetは各タスクでこの条件に紐付けて検証する。

1. **落ちない**：直近14日で articles.json 欠測ゼロ・画像8/8成功率95%以上。失敗した朝は**必ずSlackにアラート**が飛ぶ（静かな欠測をゼロに）。
2. **刺さる（オピニオン）**：全8記事に「Now on AIr の視点」＝**中立要約とは別に、山中/経営目線の解釈オピニオンが1段落**入る。「で、これは日本の中小企業の経営に何を意味するか」に答えている。
3. **伸びる（Threads）**：毎朝、**画像付き**Threads投稿が出る。TOPニュースはオピニオンをフックに単独投稿（画像=その記事のtopic_N）。URL・ブランド・ハッシュタグが全て「Now on AIr / nowonair」で正しい。
4. **使える（実用性）**：quickstart の tool.url が**実在検証済み**（404を機械チェック）。差し替え変数 `{業種}` 等が必ず入る。
5. **ブランド整合**：コードから旧 `VIGIL`/`vigil-news` が一掃され、公開文字列・投稿・URLが全て統一。
6. **見栄え（画像・二の次）**：記事タイプ（発表/数値/対立/製品）に応じてレイアウトが**最低2種**に分岐。1枚目がThreadsで映える。

### Phase 2 — 差別化：刺さる・伸びる（WS-B, WS-A）
> 目的：ここが40→100の本体。**オピニオンとThreads刷新**。順番はB→A（オピニオンが投稿のフック素材になるので先に作る）。

#### T2-1. 記事に「Now on AIr の視点」オピニオン層を追加 ★最重要
- **対象**: `pipeline/generator.py` の SYSTEM プロンプト（`generator.py:33-81`）と出力スキーマ。
- **やること**: 出力JSONに新フィールド `viewpoint`（Now on AIr独自の解釈オピニオン・120字以内）を追加する。中立の `lede`/`keypoints` は**残したまま**、その上に主張を一段重ねる。プロンプトに視点の型を与える:
  - 「このニュースを**日本の中小企業の経営**に引き付けると何を意味するか」
  - 「多くの人が見落とす点／逆張りの示唆」
  - 山中の思想（AI導入＝経営改革＝業務フロー再設計・少人数化・コスト構造。※`~/.claude/CLAUDE.md §13`）を地の視点にする。ただし**押し付けがましくせず、一次情報から逸脱しない**（憲法の「本文にない事実を足さない」を厳守）。
  - トーンは `~/.claude/skills/` の `anthropic-skills:yamanaka-voice` の型を参考にしてよいが、断定しすぎない編集後記の温度。
- **やらないこと**: 事実の捏造・過度な煽り・毎回同じ結論（「だからAI導入が大事」の連呼）。8本の viewpoint が金太郎飴にならないよう、プロンプトで「8本で切り口を変えろ」と指示。
- **表示**: `html_builder.py` の記事カードに `viewpoint` を「▶ Now on AIr の見方」として差し込む（中立要約と視覚的に区別。赤アクセントの引用ブロック等）。
- **成功条件**: 全8記事に `viewpoint` があり、要約の言い換えでなく**解釈/主張になっている**。8本で切り口が異なる。
- **検証**: `python pipeline/run.py --date 2026-07-14 --dry --skip-slides --skip-social` → `python3 -c "import json;a=json.load(open('docs/news/2026-07-14/articles.json'));[print(i,x.get('viewpoint','MISSING')) for i,x in enumerate(a,1)]"` で全件目視。金太郎飴でないこと。

#### T2-2. 本文の活用を深く（浅い要約対策）
- **対象**: `generator.py:132-133`（`top_articles[:18]`、`a['body'][:1000]`）。
- **やること**: timeout事故（コメント参照）を避けつつ、本文を **1000→1600字** に増やす。件数は18のまま。timeoutが再発するなら本数を14に落として字数を確保（品質＞本数）。
- **成功条件**: Stage2がtimeoutせず完走。lede/keypoints が本文の具体（数字・固有名詞）を反映。
- **検証**: 実行ログに `[Stage2]` エラーが出ない。生成された keypoints に一次情報の数字が入る。

#### T2-3. Threads投稿エンジンを刷新 ★ゴール直結
- **対象**: `pipeline/social_poster.py`。特に `build_post_text`（テキスト羅列）と `post_to_threads`（TEXT専用）。`run.py:124-126` の `post_dispatch` 呼び出し。
- **やること**（SNSで伸びる形に作り替え）:
  1. **画像付き投稿**にする。Threads Graph API は `media_type=IMAGE` + `image_url`（公開URL必須）で画像投稿できる。TOP記事の `topic_N` 画像（webp不可なら png）の**公開URL**（Vercel/Pages上の実URL）を使う。→ `post_to_threads` に画像対応を追加。
  2. **投稿の型を変える**: 「まとめ5件羅列」をやめ、**その日のTOP記事1本を主役**にした投稿にする。本文 = `viewpoint`（T2-1で作る独自オピニオン）をフックにした2-3文 + 「他N本は詳細へ」 + 正しいURL + `#NowOnAIr #AIニュース`。オピニオンが人の指を止める。
  3. 将来拡張として「1記事=1投稿を複数」も設計に含めてよいが、まずは**TOP1本を画像付きで確実に**（スパム化・API制限回避）。
  4. `site_url` のデフォルト引数（`social_poster.py:123`）を正しい公開URLに直す（T1-1と重複するが投稿の心臓なので二重で確認）。
- **成功条件**: `--dry` 相当で組み立てた投稿オブジェクトに ①画像URL ②オピニオン本文 ③正しいURL/ハッシュタグ が入る。本番で画像付きThreads投稿が1本出る。
- **検証**: まず投稿せずに `build_post_text` 系の出力を print して目視 → OKなら本番1回。**いきなり本番投稿しない**（外向きアクション。§下の作業プロトコル）。

**Phase 2 完了判定**: 全記事にオピニオン・Threadsが画像付き＋オピニオンフックで出る。→ commit `feat(nowonair): phase2 独自オピニオンとThreads刷新`
