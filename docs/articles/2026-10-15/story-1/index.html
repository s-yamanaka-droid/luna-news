Microsoft、AIエージェントの隔離環境「MXC」をWindows 11で一般提供

Microsoftは10月7日、AIエージェントが使えるファイルや通信先をポリシーで決め、実行時に強制する「Microsoft Execution Containers（MXC）」の一般提供を発表した。

本誌公開 2026-10-15 ｜ 本誌更新 2026-10-15 ｜ 原典の発表・執筆 2026-10-07

発行：Now on AIr 編集部（記事制作にAIを使用）｜編集責任者：山中秀斗

ニュースの要点

  • 2026年10月7日、Windows Developer Blogで一般提供を発表（Microsoft発表）
  • 開発者やIT管理者がエージェントの使えるファイルと通信先を宣言し、MXCが実行時に強制する
  • 隔離は4段階：プロセス、セッション（Windows 11のみ）、WSL、MicroVM（試験的）
  • GitHub CopilotやOpenAI Codexなどは対応済み。Anthropic Claude Codeなどは今後対応予定

任せる仕事と一緒に、触れてよい範囲を先に書き出す。

何が発表されたか

Microsoftは10月7日（米国時間）、Windows Developer Blogで、AIエージェントを隔離して動かす「Microsoft Execution Containers（MXC）」の一般提供を発表した。開発者やIT管理者がエージェントに使わせるファイルや通信先を宣言し、MXCが適切なコンテナでその範囲を実行時に強制する。

ポリシーはエージェントの外側に置かれ、エージェントや生成されたコードが自分で権限を広げることはできないと同社は説明する。設定はJSON形式のスキーマと複数言語のSDKで書き、Windows、macOS、Linuxそれぞれの隔離方式に対応付ける。

隔離は4段階から選ぶ

軽いプロセスコンテナ（WindowsではAppContainer）は、応答の速さが必要なコードやツールの実行向け。別のWindowsアカウントとセッションで動かすセッションコンテナは、長時間動くエージェント向けでWindows 11のみ。ほかにLinux向けのWSLコンテナと、ハードウェアで隔離するMicroVM（試験的）がある。

ポリシーを書き始める段階のために、許可外の操作を止めずに記録する観察モードと、止めたうえで記録する学習モードも用意した。操作の記録を出せるのはWindowsのプロセスコンテナに限られる。Windows 365でのMXC対応も一般提供になった。

対応状況と今後

GitHub Copilot、OpenClaw、OpenAI Codex、Replit、LM Studio、Unsloth AIは対応済み。Anthropic Claude Code、Box、Perplexityなどは今後対応するとしている。Intuneで組織のポリシーを管理する機能と、Microsoft Entraでエージェントの操作を人の操作と区別する機能は「近く」提供予定で、今回の一般提供には含まれない。

日本語ではPublickeyが10月15日に報じた。本誌は内容をMicrosoftの原典で確認したが、MXCを実機で検証してはいない。

本誌の考察・実務提案

Lakkanの視点｜まず「観察」で必要な範囲を洗い出す

エージェントに任せる仕事を決めても、必要なフォルダーや通信先を最初から正確に書くのは難しい。試験用の作業を観察モードや学習モードで動かし、記録から本当に必要な範囲だけを許可する順番が現実的だ。

社内の端末で使う場合、Intuneとの連携が提供されるまでは、誰がどのポリシーを承認するかを先に決めておきたい。これは本誌の運用提案で、Microsoftの推奨手順ではない。

現場で試す3つのこと

  1. エージェントに任せたい作業を1つ選び、触れるフォルダーと通信先を書き出す
  2. 使っているエージェントがMXCに対応済みか、対応予定かを確認する
  3. 試験用の環境で記録を取り、許可する範囲を絞ってから本番に移す
