Microsoft、自社製コード生成AI「MAI Code 2」をGitHub Copilotに投入　競合の96〜98%の性能を5〜40%の費用でと主張、軽量版は無料プランでも

Microsoftは11月17日、年次イベント「Ignite」で自社開発のAIモデル群を発表した。中心はプログラミング向けの「MAI Code 2」と軽量版「MAI Code 2 Flash」で、同日からGitHub Copilotで選べる。同社によると、MAI Code 2は4つのベンチマークの平均でGPT-6.1 Solの98%の性能を約4割の費用で出すという。

ニュースの要点

  • MAI Code 2は本番向けのコード作成、難しい不具合調査、複数ファイルにまたがる実装、画面づくり向け。Flashはコードの説明や小さな修正を大量にこなす用途
  • GitHub Copilotでは、MAI Code 2がPro、Pro+、Max、Business、Enterprise、FlashはFreeとStudentを含む全プランで利用できる
  • 同社によると、MAI Code 2はGPT-6.1 Solの98%の性能を約40%の費用で、Claude Opus 5.5の96%の性能を5%の費用で出す
  • 同じ日に画像生成のMAI Image 2.7、音声対話のMAI Realtime 1、防御向けのMAI Cyber 2 Flashなども発表した

少し劣っても、ずっと安い。

2つのコード向けモデル

Microsoftは11月17日、自社のAI部門が開発したMAI Code 2とMAI Code 2 Flashを発表した。MAI Code 2は本番に出すコードの作成、深い不具合調査、複数ファイルにまたがる実装、リポジトリ全体を見た推論に向け、ダッシュボードなど画面づくりにも調整したという。Flashはコードの説明、狙いを絞った修正、定型的な直し、短い試行の繰り返しを受け持つ。同社は、どちらも基礎科学の研究やとても長い自律作業のような難しい問題には「まだ調整していない」と明記している。

性能について同社は、DeepSWE 1.1、Terminal Bench 2.1、SWE-Atlas、FrontierCode v1.1の4つの平均で、MAI Code 2がGPT-6.1 Solの98%の性能を約40%の費用で、Claude Opus 5.5の96%の性能を5%の費用で出すとしている。Flashは日常的なコーディングの3つのベンチマークで、GPT-6 LunaやClaude Haiku 5.5と同程度だという。いずれも同社の測定で、全モデルを最大の推論設定にし、GitHub Copilot CLIで測ったと説明している。料金の金額は発表に書かれておらず、未確認である。

GitHub Copilotでの提供と、ほかの発表

GitHubによると、MAI Code 2はCopilotのPro、Pro+、Max、Business、Enterpriseで、FlashはFreeとStudentを含む全プランで、年間プランの対象契約者が使える。VS Code、Visual Studio、Copilot CLI、github.com、GitHub Mobile、JetBrains、Xcode、Eclipseなどのモデル選択画面から選ぶ。料金は使用量に応じた課金である。BusinessとEnterpriseでは、管理者がモデルの利用方針で管理し、既定では新しいモデルは自動で有効になる。Flashは開発基盤のMicrosoft Foundryで限定プレビューとなり、OpenRouterやVercelなどへの提供も「近く」としている。

Microsoft AIはIgniteの発表で、自社モデル7つを出したとしている。コード向けの2つのほか、画像生成・編集のMAI Image 2.7とその軽量版、音声で会話するMAI Realtime 1（音声1分あたり0.01ドルから）、サイバー防御向けのMAI Cyber 2 Flashなどを挙げた。7つの数え方は発表ページの一覧と見出しで一致しておらず、本誌では内訳を確定できていない。

本誌の考察・実務提案

Lakkanの視点｜Copilotの「中身」が選べる時代の管理

これは本誌の解釈だが、今回の意味は、MicrosoftがGitHub Copilotの裏側で動くモデルを他社製だけに頼らず、自社製でも賄い始めたことにある。性能は他社の上位モデルにわずかに届かないが、費用が大きく下がるという売り方で、日常の大量の作業を安いモデルに寄せる流れをはっきりさせた。

本誌は、Copilot BusinessやEnterpriseを使う企業に、新しいモデルが既定で自動的に有効になる設定のままでよいかを確認することを勧める。社内のコードをどのモデルに渡してよいかの方針がある会社では、知らないうちに選択肢が増えることになる。これは本誌の提案で、Microsoftの推奨ではない。

現場で試す3つのこと

  1. Copilot BusinessやEnterpriseの管理者は、新モデルを既定で有効にする設定を見直す
  2. コードの説明や小さな修正など、軽量モデルに任せられる作業を洗い出す
  3. 使用量課金の明細で、モデルごとの費用を月に一度確認する
