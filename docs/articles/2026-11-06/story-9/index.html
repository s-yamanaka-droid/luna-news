GitHub NextとMicrosoft Research、AIが書いたコードを数学的に証明する「PDD Kit」を公開　Rustが対象の研究試作

GitHub NextとMicrosoft Researchは、AIが書いたコードが仕様どおりに動くことを数学的な証明で確かめる研究試作「PDD Kit（Proof-Driven Development）」を公開した。対話で要求を検証できる仕様にまとめ、コーディングエージェントが実装と証明を書き、検証ツールVerusが確かめる。現在はRustが対象だ。

ニュースの要点

  • GitHub NextとMicrosoft Researchの共同研究。位置づけは研究試作（Research Prototype）
  • 計画ツールChopinの中で、レビュー担当が聞くような質問をして要求を仕様にまとめる
  • コーディングエージェントが実装と証明を書き、Rust向けの検証ツールVerusが確かめる。証明できない部分はテストで補う
  • 約5,000行のRustアプリ「Pet Store」のログイン処理で、正しいパスワードにだけトークンを出すことなどを確かめた

人は仕様を決め、確認は機械に任せる。レビューの分担が変わり始めた。

何を公開したか

GitHub NextとMicrosoft Researchは、AIが生成したコードが仕様を満たすことを数学的な証明で確かめる研究試作「PDD Kit（Proof-Driven Development）」を公開した。エージェントが大量のコードを書くようになり、すべての行を人が読んで確かめるのが難しくなっているという問題意識から作られた。

PDD Kitは、同チームの計画ツール「Chopin」の中で計画の相談相手として動く。レビュー担当が聞くような質問をして答えを記録し、形式化できる部分を検証ツール「Verus」の仕様に変える。コーディングエージェントが実装と証明を書き、Verusがそれを確かめる。証明できない部分はテストで補う。

試した例と現時点の制約

例として、約5,000行のRust製Webアプリ「Pet Store」のログイン処理を取り上げた。正しいパスワードの場合にだけトークンを出す、管理者アカウントにだけ管理者用トークンを出す、という2つの要求を検証したという。

VerusがRust向けのツールのため、現在検証できるのはRustだけだ。位置づけは研究試作で、プロジェクトページに一般の利用申し込みの方法は書かれていない。ほかの言語への対応予定は未確認。

本誌の考察・実務提案

Lakkanの視点｜「全部読む」から「仕様を決めて証明させる」へ

AIが書くコードの量が増えると、人のレビューが追いつかなくなる。PDD Kitは、人は何を満たすべきかという仕様づくりに集中し、満たしているかの確認は機械に任せるという分担を試している。

すぐに業務で使える段階ではないが、本誌は、認証や課金のように誤りの影響が大きい処理から、満たすべき条件を文章で書き出しておくことを勧める。これは本誌の提案で、GitHubの推奨ではない。

現場で試す3つのこと

  1. 認証や課金など、誤りが許されない処理を3つ挙げる
  2. その処理が満たすべき条件を、箇条書きで書き出す
  3. AIが書いたコードのテストが、その条件を確かめているかを点検する
