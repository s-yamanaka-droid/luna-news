Gemini API、使うツールの定義だけを後から読み込む「Tool Retrieval」をプレビュー提供　入力トークンを削減、追加料金なし

Googleは11月19日、Gemini APIのInteractions APIで「Tool Retrieval」のプレビュー提供を始めた。多数のツールを登録しても、最初は名前と説明だけを読み込み、必要になったツールの詳しい定義だけを後から読み込むため、入力トークンを減らせる。

本誌公開 2026-11-21 ｜ 本誌更新 2026-11-21 ｜ 原典の発表・執筆 2026-11-19

発行：Now on AIr 編集部（記事制作にAIを使用）｜編集責任者：山中秀斗

ニュースの要点

  • 提供状態はプレビュー。対象はGemini APIのInteractions API
  • 使い方：リクエストに {"type": "tool_search"} を加え、後から読み込みたいツールに defer_loading: true を設定する
  • 対応モデルはGemini 3.6以降（Gemini 4の全モデルを含む）。リモートのMCPサーバーのツールにも対応
  • 別料金はなし。tool_searchが少量の固定入力トークンを加え、読み込んだツール定義は通常どおり入力として課金される

ツールは、必要な時に必要な分だけ。

仕組み

Googleは11月19日、開発者向けブログでGemini APIの新機能「Tool Retrieval」を発表した。AIエージェントに多くのツール（外部サービスを呼び出す機能）を持たせると、すべての定義を毎回モデルに渡すため入力トークンがかさむ。Tool Retrievalでは、最初はツールの名前と説明だけを読み込み、必要になったツールの引数などの定義を後から読み込む。

使うには、リクエストに {"type": "tool_search"} を加え、後から読み込みたいツールに defer_loading: true を設定する。ツールの検索はGoogleのサーバー上で行うため索引を作る必要はなく、検索を自社側で行う設定（execution: "client"）も選べる。リモートのMCPサーバーのツールにも対応する。

対象と料金

対象はInteractions APIで、提供状態はプレビュー。対応モデルはGemini 3.6以降で、Gemini 4の全モデルを含む。

別料金はかからず、通常のモデル料金で使える。tool_searchが少量の固定の入力トークンを加え、読み込んだツール定義は通常のツールと同じく入力として課金される。どの程度トークンが減るかは使い方によって変わり、一般提供の時期は書かれておらず、未確認である。

本誌の考察・実務提案

Lakkanの視点｜ツールが増えるほど効く節約策

これは本誌の解釈だが、社内の業務システムをMCPなどでAIにつなぐほど、ツールの数は数十〜数百に増える。そのたびにすべての定義を渡す作りでは、費用と応答速度の両方が悪くなる。必要な分だけ読み込む方式は、他社のAPIでも広がっている考え方だ。

本誌は、Gemini APIでエージェントを作っている開発チームに対し、まず利用頻度の低いツールから defer_loading を付け、導入前後で入力トークン数と回答の正確さを比べることを勧める。これは本誌の提案で、Googleの推奨ではない。

現場で試す3つのこと

  1. 自社のAIエージェントに登録しているツールの数と、1回あたりの入力トークン数を確認する
  2. 利用頻度の低いツールを選び、プレビューで後から読み込む設定を試す
  3. 導入前後でトークン数と回答の正確さを比べる
