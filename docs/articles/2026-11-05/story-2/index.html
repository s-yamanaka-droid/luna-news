Cloudflare、利用者の代わりに動く「個人エージェント」の可視化と制御を追加　広告のあるページだけ遮断する設定も

Cloudflareは11月4日、利用者の代わりにサイトを訪れるAIの「個人エージェント」について、サイト運営者がアクセスの量を把握し、エージェントごとに許可や遮断を選べる機能を発表した。広告を載せたページだけ遮断する選択肢も加えた。

本誌公開 2026-11-05 ｜ 本誌更新 2026-11-05 ｜ 原典の発表・執筆 2026-11-04

発行：Now on AIr 編集部（記事制作にAIを使用）｜編集責任者：山中秀斗

ニュースの要点

  • Security Analyticsのボット分析に「Personal Assistants」の区分を追加し、エージェントごとのリクエスト数を表示する
  • Agentsのポリシーを「AI Crawler and Agent access policies」に改め、エージェントごとに許可・広告ページで遮断・遮断を選べる
  • Account Abuse Protectionでは、ログインや登録がエージェント経由かどうかを確認できる。こちらは早期アクセス
  • サイト追加時に広告で収益化しているかを尋ね、推奨ポリシーを出し分ける

AIエージェントは、遮断すべきボットではなく顧客の代理人になりつつある。

何が追加されたか

Cloudflareは11月4日のブログで、利用者の依頼を受けて商品比較や問い合わせ、購入などを代行する「個人エージェント」への対応を発表した。Security Analyticsのボット分析に「Personal Assistants」の区分が加わり、どのエージェントが何件のリクエストを送っているかを一覧できる。エージェントで絞り込むと、アクセス先のパスやステータスコードも確認できる。

これまでの「Agents」ポリシーは「AI Crawler and Agent access policies」に名前を変え、エージェントごとに「許可」「広告のあるページで遮断」「遮断」を選べるようにした。検索向けや学習向けのポリシーは変わらない。新しくサイトを追加する際には、広告で収益化しているページがあるかを尋ね、答えに応じた推奨設定を示す。

不正対策の側面と提供状況

Account Abuse Protectionでは、エージェントがどの利用者の代わりに動いているか、ある口座に対してどのエージェントが動いているかを見られる。ログインや新規登録がエージェント経由かどうかも表示する。攻撃者がエージェントを悪用していれば、その口座に絞ったWAFルールで対処でき、同じエージェントを使うほかの利用者は遮断せずに済むという。

Account Abuse Protectionは「早期アクセス」と明記されている。分析画面とポリシー設定の提供範囲（対象プラン）や料金はブログに記載がなく、未確認。

本誌の考察・実務提案

Lakkanの視点｜「AIからのアクセス」を一律に止める時代は終わる

Cloudflare自身がブログで、エージェントを一律に遮断すると顧客を失うおそれがあると書いている。AIに買い物や予約を頼む利用者が増えれば、エージェントは「ボット」ではなく「顧客の代理人」として扱う必要が出てくる。

本誌は、ECや予約サイトを運営する企業は、エージェントに開くページと閉じるページを、広告収益や不正リスクと合わせて一度棚卸しすることを勧める。これは本誌の提案で、Cloudflareの推奨ではない。

現場で試す3つのこと

  1. 自社サイトのアクセス解析で、AIエージェント由来のアクセスがあるか確かめる
  2. エージェントに使ってほしいページと、止めたいページを分けて書き出す
  3. Cloudflare利用中なら、AI Crawler and Agent access policiesの現在の設定を確認する
