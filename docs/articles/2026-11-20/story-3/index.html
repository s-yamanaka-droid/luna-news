Next.js、2026年のセキュリティ告知は51件に　AIで古い欠陥が見つかりやすくなったと説明、全プルリクエストをAIが攻撃者目線で点検

ウェブ開発の枠組み「Next.js」の開発チームは11月17日、セキュリティ告知が2024年の6件から2026年は51件に増えた理由を説明した。AIによって古いコードの欠陥が安く見つかるようになったためで、51件の70%は1年以上前のコードにあったという。新しいコードについては、AIが全てのプルリクエストを攻撃者の目線で点検する仕組みを入れた。

ニュースの要点

  • セキュリティ告知は2024年6件、2025年14件、2026年は11月17日時点で51件
  • 2026年の51件のうち70%は1年以上前のコード、43%は3年以上前のコードにあった
  • Vercel Agentの「Security Review」が全てのプルリクエストで攻撃を試み、レビューとテストを通った変更の問題も見つけた
  • Next.js 16.4から、既知の脆弱性がある版を使うと next dev と next build が警告する

告知の数より、直すまでの日数を見る。

告知が増えた理由

Next.jsの開発チームは11月17日、公式ブログで、セキュリティ告知が2024年の6件、2025年の14件から、2026年は51件（11月17日時点）に増えた理由を説明した。答えは「AIで欠陥を見つけやすくなった」ことだという。これまで見つけにくい、あるいは悪用しにくいとして残っていた欠陥が、AIによって安く見つかり、悪用もしやすくなった。

2026年に見つかった51件のうち70%は1年以上前のコード、43%は3年以上前のコードにあった。画像の最適化などで使う外部ライブラリの欠陥も多く、Next.js本体ではない部分に深刻な問題があったとしている。修正をまとめて届けるため、セキュリティ更新はおおむね月1回、事前に予告して出す形にした。

新しいコードの点検と、利用者向けの警告

新しいコードについては、Vercel Agentの「Security Review」が全てのプルリクエストで、独自のセキュリティ指針に沿って攻撃を試みる。コードレビューと自動テストを通り、取り込む直前だった変更から問題を見つけた例もあるという。報告の受付や再現、深刻度の判断には、Eveで作った社内ボットを使っている。

利用者向けには、Next.js 16.4から、既知の脆弱性がある版を使っていると next dev と next build が警告を出す。npx next@canary upgrade --agent を実行すると、修正済みの最新版を選び、コーディングエージェントに更新作業を渡す。AIを使った攻撃が実際にどれだけ増えたかは、発表には示されておらず未確認である。

本誌の考察・実務提案

Lakkanの視点｜「告知が多い」ことより「更新が遅い」ことが危ない

これは本誌の解釈だが、告知の増加はNext.jsだけの問題ではなく、古くから使われている部品ほどAIで欠陥が掘り起こされる流れを示している。危ないのは告知の数ではなく、告知が出てから自社のサイトが更新されるまでの時間である。

本誌は、Next.jsで作ったサイトを持つ企業に、版の確認と月1回の更新日をあらかじめ運用表に入れておくことを勧める。外注先が保守している場合は、更新の担当と期限を契約で確かめておきたい。これは本誌の提案で、Vercelの推奨ではない。

現場で試す3つのこと

  1. 自社と取引先が運用するNext.jsのサイトを洗い出し、使っている版を確認する
  2. 月1回のセキュリティ更新に合わせて、適用日と担当を運用表に入れる
  3. 外注先の保守契約に、セキュリティ更新の対応期限が書かれているか確認する
