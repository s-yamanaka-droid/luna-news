Microsoft、複数のデータベースを一か所で見る「Database Hub」を正式提供　異常を見つけて根拠と対策を示すエージェントはプレビュー

Microsoftは11月17日、Microsoft Fabric上で社内の複数のデータベースを一覧・監視・調査できる「Database Hub」を正式提供すると発表した。あわせて、選んだデータベースを見張り、問題があれば根拠と推奨対策を示す「Database Agents」をパブリックプレビューで公開した。

Database Hubで何が見えるか

Microsoftは11月17日、Azure SQLの公式ブログで、Microsoft Fabric上の「Database Hub」の正式提供を発表した。対象はAzure SQL、Azure Database for PostgreSQL、Azure Cosmos DB、SQL Server、SQL database in Fabric。対応するデータベースを一覧にし、性能、セキュリティ、最適化の面で「注意が必要なもの」をまとめて示す。

性能面ではCPU、メモリ、ストレージの推移をほぼリアルタイムで追う。セキュリティ面では、公開ネットワークからのアクセスや、プライベート接続・利用者管理の暗号鍵が設定されていない点などを指摘する。指摘から該当するデータベースへたどって調べることもできる。

AIエージェントと料金の条件

パブリックプレビューの「Database Agents」は、選んだデータベースを見張り、正常なうちは何も知らせない。対応が必要なときは根拠と推奨を添えて問題を挙げ、次にどうするかは利用者が決める。自然な文章で質問できるCopilotによる調査や、Azure SQL Database向けの通知機能もプレビューとして加わった。

新規利用者には無料のFabricライセンスが自動で付く。ダッシュボードの共有、独自の通知の作成、Copilotの利用にはFabricの容量契約が必要になる。金額は発表に書かれておらず、未確認である。

本誌の考察・実務提案

Lakkanの視点｜まず「どこに何があるか」を把握する道具として

これは本誌の解釈だが、データベースが部署ごと・クラウドごとに散らばった企業では、AIに監視を任せる前に、そもそも何がどこにあるかが分からないことが多い。正式提供された一覧と指摘の機能は、その棚卸しに使いやすい。

本誌は、Azureを使っている企業に、まず一覧機能で公開ネットワークに開いているデータベースを確かめ、エージェントはプレビューとして検証環境で試すことを勧める。これは本誌の提案で、Microsoftの推奨ではない。

現場で試す3つのこと

  1. 社内のデータベースを、管理部署・クラウド・用途ごとに一覧にする
  2. 公開ネットワークからアクセスできる設定のデータベースがないか確認する
  3. Database Agentsは本番ではなく検証環境で試し、提案の妥当性を記録する
