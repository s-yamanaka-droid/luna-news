ニュースの要点

  • MIGは1つのGPUを最大7つの区画に分ける機能で、区画ごとに計算資源・メモリ・メモリ帯域を持ち、ハードウェアで分離される
  • 対応はP4d（A100）とP5（H100）が最大7区画、G7（RTX PRO 4500 Blackwell）が2区画、G7e（RTX PRO 6000 Blackwell Server Edition）が4区画
  • 推論コンポーネントを使うエンドポイントのみ対象。単一モデルやサーバーレスのエンドポイントは対象外
  • 新しいAPIは追加せず、既存の呼び出しに2つの任意項目を足す形。省略すれば従来どおり動く

遊んでいるGPUは、分ければ働く。

何を発表したか

AWSは11月6日、Amazon SageMakerの推論エンドポイントがNVIDIAのMulti-Instance GPU（MIG）に対応したと発表した。MIGは1つのGPUを最大7つの区画に分ける機能で、区画ごとに専用の計算資源、メモリ、メモリ帯域を持ち、分離はハードウェアで行われる。GPUの数より多くのモデルを、互いに分離した状態で載せられる。

対応するのはP4d（NVIDIA A100、40GB）とP5（H100、80GB）がGPUあたり最大7区画、G7（RTX PRO 4500 Blackwell、32GB）が2区画、G7e（RTX PRO 6000 Blackwell Server Edition、96GB）が4区画。区画ごとにモデルが常に読み込まれるため、立ち上がりの待ちやモデルの入れ替えが起きないとしている。

使える条件

対象は推論コンポーネントを使うエンドポイントに限られ、単一モデルのエンドポイントやサーバーレスのエンドポイントは対象外。区画の配置はエンドポイントを作るときに決め、複数のGPUを必要とするモデルは引き続きGPUをまるごと使う。新しいAPIは追加せず、既存の呼び出しに2つの任意の項目を加える形で、省略すれば従来どおり動く。

これまではMIGを使うには自前のKubernetes環境で運用する必要があったが、SageMakerがGPUの構成、配置、拡張を管理する。区画の構成によって準備時間は試験で約17秒延びたという。対応リージョンや料金は確認した範囲の発表文に記載がなく、未確認。

本誌の考察・実務提案

Lakkanの視点｜小さなモデルほど「GPUの空き」を見直す価値がある

これは本誌の解釈だが、社内用の小さめのモデルを複数動かしている場合、GPUを1台ずつ割り当てて大半が遊んでいることは珍しくない。区画に分けて載せられれば、台数を減らせる余地がある。

本誌は、推論にGPUを使っている企業は、モデルごとのGPU使用率とメモリ使用量を1週間ほど記録し、まとめられる組み合わせを洗い出すことを勧める。これは本誌の提案で、AWSの推奨ではない。

現場で試す3つのこと

  1. 推論に使っているモデルごとに、GPU使用率とメモリ使用量を1週間記録する
  2. 1つのGPUにまとめられそうなモデルの組み合わせを書き出す
  3. まとめた場合に互いの応答速度へ影響が出ないか、試験環境で確かめる
