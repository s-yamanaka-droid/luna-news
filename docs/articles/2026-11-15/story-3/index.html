Cloudflare、AIエージェント向けの軽量ブラウザ「Kitesurf」をオープンソース化　Apache 2.0で公開、Puppeteerからそのまま接続できる

Cloudflareは11月13日、AIエージェント向けの実験的なブラウザエンジン「Kitesurf」のソースコードをGitHubで公開した。ライセンスはApache 2.0。ブラウザ用のコンテナを使わずにCloudflare Workersの上だけで動き、ページの読み込みからスクリーンショットの作成までを行う。

ニュースの要点

  • ソースコードをApache 2.0でGitHubに公開。8月の発表時に示していた公開の約束を果たした
  • HTMLの解析、CSSの適用、ページ内のJavaScriptの実行、スクリーンショットの作成を、ブラウザ用コンテナなしで行う
  • Chrome DevTools Protocol（CDP）に対応し、Puppeteerなどの既存の道具から接続できる
  • 自分のCloudflareアカウントに置くにはWorkersの有料プランが必要。開発はまだ活発に続いている段階

AIが使うブラウザは、人のものと同じでなくていい。

何が公開されたか

Cloudflareは11月13日、Kitesurfのソースコードを公開した。Kitesurfは同社が8月に発表した、AIエージェント向けの実験的なブラウザエンジンである。状態を持たない作りで、全体がCloudflare Workersの上で動く。9月の続報ではWebMCPへの対応や新しいAPIが加わっていた。ねらいは、Chromiumより少ないCPUとメモリで動き、同社のネットワーク上で必要なときに必要なだけ増やせる、エージェント向けの軽いブラウザを作ることだという。

ライセンスはApache 2.0。中身はRustで書かれた部品をWebAssemblyにしたもので、HTMLの解析と配置・描画にBlitz、CSSにStylo、文字組みと2次元の描画にLinebenderのライブラリ、PDFの出力にKrillaを使う。JavaScriptの実行は基本的にCloudflareのDynamic Workersで行い、それができない場合の最後の手段としてBoaというエンジンを使う。

どう使うか、どこまでできるか

手元のPCでは、公開されたリポジトリを取得して依存関係を入れ、開発用のサーバーを立ち上げると動く。初回はRustの部品を組み立てるため時間がかかる。Chrome DevTools Protocol（CDP）に対応しているので、Puppeteerから接続してページを開き、スクリーンショットを撮れる。AIエージェントの実行環境から、このCDPの接続口につなぐこともできるとしている。

自分のCloudflareアカウントに置く場合は、ページごとに隔離した実行環境を作るDynamic Workersを使うため、Workersの有料プランが必要になる。同社は、管理された「Browser Run」のAPIに代わる選択肢と位置づけている。開発はまだ活発に続いており、重点は互換性、信頼性、効率だという。修正を送る前に、まず再現手順か方針を書いた課題を出し、保守担当者の同意を得る手順を求めている。実際のウェブサイトがどの程度正しく表示されるかの数字は、発表の本文には書かれていない。

本誌の考察・実務提案

Lakkanの視点｜AIにウェブを見せる費用が下がる

これは本誌の解釈だが、AIエージェントにウェブを操作させる仕事では、ブラウザを動かす費用と待ち時間が積み重なる。人が使うのと同じ重いブラウザを1件ごとに立ち上げるのは無駄が多い。Kitesurfはそこを軽くする試みで、ソースが公開されたことで、中身を確かめながら使えるようになった。

ただし実験的と明記されており、すべてのサイトが正しく表示されるわけではない。本誌は、社内でウェブの情報収集を自動化している企業に、いま使っている仕組みを置き換える前に、よく使うサイト10件ほどで表示と動作を比べることを勧める。これは本誌の提案で、Cloudflareの推奨ではない。

現場で試す3つのこと

  1. ウェブを自動で読む社内の仕組みがあれば、月の実行回数と費用を一度数える
  2. よく読むサイト10件で、Kitesurfと現行のブラウザの表示結果を比べる
  3. 本番で使う前に、対応していないサイトに当たったときの代わりの経路を決めておく
