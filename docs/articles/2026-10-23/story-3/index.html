AnthropicとOpenAI、AIの共通規格を財団に寄贈　「Agent Skills」と「Open Responses」

Linux Foundation傘下のAgentic AI Foundation（AAIF）は10月22日、AnthropicのAIエージェント向け手順の標準「Agent Skills」と、OpenAIのLLM API共通仕様「Open Responses」など4つを新たに受け入れると発表した。特定の企業に縛られない共通の規格として、財団のもとで開発を続ける。

本誌公開 2026-10-23 ｜ 本誌更新 2026-10-23 ｜ 原典の発表・執筆 2026-10-22

発行：Now on AIr 編集部（記事制作にAIを使用）｜編集責任者：山中秀斗

ニュースの要点

  • AAIFが新たに受け入れたのはAgent Skills（Anthropic）、Open Responses（OpenAI）、OpenEnv（Hugging Face）、OpenSandbox（Alibaba）の4つ。財団の管理プロジェクトは2025年12月の発足時の3つから10になった
  • Agent Skillsは、AIエージェントが必要なときに読み込む手順・スクリプト・資料をまとめる形式。Anthropicによると70を超えるエージェント製品が対応し、公開されたスキルは約100万、インストールは約2億8,000万回
  • Open Responsesは、OpenAIのResponses APIを基にした、複数のAI提供元で共通に使えるLLM APIの仕様。共通のデータ形式、ストリーミングのイベント、拡張できるツールの仕組みを定める
  • Agent Skillsの名称・ロゴ・GitHub組織・agentskills.ioのドメインも財団へ移る。Anthropic、Google、OpenAIなどの技術者が個人の立場で保守する。日本企業の対応状況は未確認

AIへの手順書と呼び出し口が、一社のものから共有のものへ。

財団が受け入れた4つのプロジェクト

AAIFは10月22日、米サンノゼで開いたイベント「AGNTCon + MCPCon North America」に合わせて、4つの新しいプロジェクトを発表した。AnthropicのAgent Skills、OpenAIのOpen Responses、Hugging Faceの強化学習用の環境づくりの枠組み「OpenEnv」、Alibabaの汎用サンドボックス基盤「OpenSandbox」だ。

AAIFは2025年12月、Anthropic、Block、OpenAIが共同で立ち上げた財団で、AIと外部のサービスをつなぐ規格MCPなど3つのプロジェクトで始まった。今回の追加で、A2A、AGENTS.md、gooseなどを含め10のプロジェクトを抱えることになった。

Open Responsesは、OpenAIのResponses APIを基に、複数の提供元で共通に使えるLLMのAPIを定める仕様だ。共通のデータ形式、一貫したストリーミングのイベント、拡張できるツールの仕組みを定める。発表ではOpenAIのSteve Coffey氏がコメントを寄せたが、どの企業が実装しているかは財団の発表には書かれておらず、本誌は未確認だ。

Agent Skillsの移管の中身

Anthropicは同日の発表で、Agent Skillsの標準に加え、名称とロゴ、GitHubの組織、agentskills.ioのドメインを財団に移すと説明した。Agent Skillsは2025年12月に公開した標準で、Anthropicによると、ChatGPT、Cursor、GitHub Copilot、VS Codeなど70を超えるエージェント製品が対応している。公開されたスキルは約100万、インストールは約2億8,000万回にのぼるという。

今後はAnthropic、Google、OpenAIなどの技術者が個人として保守し、AnthropicのDavid Soria Parra氏とMahesh Murag氏が主な保守担当を務める。Anthropicは、版ごとのリリース、正式な提案手続き、スキルを作る人・入れる人向けの安全の指針を含む今後の計画を提案した。財団に加盟しなくても、標準を使ったり議論に加わったりできるとしている。

本誌の考察・実務提案

Lakkanの視点｜社内の「AIへの指示」を、特定のAIに閉じ込めない

Agent Skillsは、社内で整えた業務手順をAIに渡す形式で、Open ResponsesはAIを呼び出す側の共通の窓口だ。どちらも、使うAIを替えたときに作り直す手間を減らす方向の動きといえる。今後AIの導入を進める中小企業にとっては、手順書や呼び出しの仕組みを一社専用の形で作り込みすぎないことが、乗り換えの余地を残すことにつながる。

ただし、財団へ移ったことと、各社の製品で同じように動くことは別の話だ。自社で使うAIがどこまで対応しているかは、個別に確かめる必要がある。これは本誌の提案で、AAIFやAnthropic、OpenAIの推奨ではない。

現場で試す3つのこと

  1. 社内でAIに渡している手順書やプロンプトの置き場所を洗い出し、Agent Skillsの形式（agentskills.io）で書けるか試す
  2. 使っているAIツールがAgent Skillsに対応しているかを、提供元の資料で確認する
  3. 自社でAIを呼び出す仕組みを作る場合は、制作会社にOpen ResponsesなどAI提供元を替えやすい作りにできるか相談する
