AWS、AIでコードの脆弱性を検証・修正する「Continuum」を一般提供　米国2リージョン、100万行200ドルから

AWSは10月22日、コードの脆弱性を見つけ、実際に悪用できるかを隔離環境で確かめたうえで修正案まで出すサービス「AWS Continuum for code vulnerabilities」の一般提供を始めた。複数の最先端AIモデルを使い分ける仕組みで、提供地域は米国東部（バージニア北部）と米国西部（オレゴン）の2つだ。

本誌公開 2026-10-23 ｜ 本誌更新 2026-10-23 ｜ 原典の発表・執筆 2026-10-22

発行：Now on AIr 編集部（記事制作にAIを使用）｜編集責任者：山中秀斗

ニュースの要点

  • GitHubかAmazon S3のコードを定期または随時スキャンし、悪用できるかを隔離環境で再現して確認、事業への影響で優先順位を付ける
  • 修正はコードの差分、依存ライブラリの更新、設定変更として作り、GitHubのプルリクエストで出す。適用には必ず人の承認が必要
  • 料金は保護するコード100万行あたり月200ドル（最初の1,000万行まで）と、推論1単位（CIU）10ドル。100万行・脆弱性100件の試算で月1,200ドル
  • 提供は米国東部（バージニア北部）と米国西部（オレゴン）のみ。東京リージョンは対象外。対応するプログラミング言語は発表に記載がない

見つけるだけでなく、本当に危ないかを確かめてから直す。

見つけた脆弱性を「悪用できるか」で絞り込む

AWSは10月22日、「AWS Continuum for code vulnerabilities」の一般提供を発表した。コードの脆弱性を見つけ、自社の環境で実際に悪用できるかを確かめ、事業への影響で順位を付け、修正を作るまでを一つのサービスで行う。発表ブログは、攻撃者が最先端のAIモデルを使って、公表された脆弱性から攻撃コードを素早く作れるようになったことを背景に挙げている。

使い方は、GitHubかAmazon S3にあるコードを接続し、スキャンの間隔を決めるか、必要なときに実行する。AWSの構成情報を取り込めば、その部品が本番で使われているか、外から届くかといった文脈も判断に使う。再現できる脆弱性は隔離した環境で実際に攻撃を試し、証拠の強さを付けて報告する。修正はコードの差分、依存ライブラリの更新、設定変更のいずれかとして作り、GitHubのプルリクエストで出す。AWSは「すべての修正に人の承認が必要」としており、自動適用は今後の機能と説明している。

AIの使い方と料金

AWSの製品ページによると、Continuumは特定のモデルに依存せず、複数の最先端のセキュリティ向けAIモデルから作業ごとに適したものを選ぶ。利用者がモデルの利用契約を別に結ぶ必要はない。どのモデルを使っているかは公表していない。製品ページには、HENNGEやクラスメソッドなど日本企業のコメントも載っている。

料金は2本立てだ。保護するコードの行数に応じた月額は、最初の1,000万行まで100万行あたり200ドルで、量が増えると下がる。これとは別に、AIの処理量を表す「Continuum推論ユニット（CIU）」が1単位10ドルかかる。AWSの試算では、100万行のコードで脆弱性100件（各1単位）なら月1,200ドル、1,000万行・1,000件なら月1万2,000ドル。実際の推論量は脆弱性ごとに変わる。無料枠の記載はない。提供地域は米国東部（バージニア北部）と米国西部（オレゴン）で、東京リージョンは含まれない。対応するプログラミング言語は発表に記載がなく、本誌未確認だ。

本誌の考察・実務提案

Lakkanの視点｜脆弱性は「数」ではなく「本当に危ないもの」から

脆弱性を見つける道具は多いが、現場で困るのは大量の指摘のうちどれから直すかだ。Continuumは「実際に悪用できるか」を確かめて絞り込む点に重心を置いている。前号で伝えたPHPの脆弱性のように、AIで欠陥が見つかる速さが上がるほど、優先順位付けの手間が増える。

ただし料金はAIの処理量で変わり、小さなコードでも月1,000ドル超の試算になる。自社開発のコードが少ない中小企業は、まず開発委託先や制作会社が脆弱性の指摘をどう優先順位付けしているかを聞くところから始めたい。データを米国リージョンに置けるかも、導入前に確認が必要だ。これは本誌の提案で、AWSの推奨ではない。

現場で試す3つのこと

  1. 自社や委託先が使う脆弱性スキャンの指摘件数と、どれから直しているかの基準を確認する
  2. 導入を検討する場合は、AWSの料金ページの試算をもとに、自社のコード行数と過去の指摘件数で月額の目安を出す
  3. 米国リージョン（バージニア北部・オレゴン）にコードを預けてよいか、社内規程や取引先との契約を確かめる
